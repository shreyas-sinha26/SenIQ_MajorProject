SenIQ API

Run backtests, evaluate live signals, and read your strategies & paper deployments — from any script, notebook, or AI agent.

Authentication

Every request needs an API key in the Authorization header. Keys are personal: each user creates their own (up to 5, named, revocable) in Profile → API Access. The full key is shown once at creation. API access requires the Pro plan — a downgrade or revocation cuts a key off on its very next request.

Authorization: Bearer seniq_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

Rate limits

Per key, per hour, shared across this REST API and the MCP server — one key = one budget, however you call it.

BucketLimitApplies to
heavy30 / hourbacktest, signals, paper state
light240 / hourcatalog, validate, listings, index

Responses carry X-RateLimit-Limit and X-RateLimit-Remaining; a 429 adds Retry-After (seconds).

Endpoints

GET/v1

Index + key check: endpoint list, rate limits, disclaimer.

curl https://YOUR-HOST/v1 -H "Authorization: Bearer $SENIQ_KEY"

GET/v1/strategies

Strategy catalog — built-in strategies with parameter schemas, plus the builder vocabulary (indicators, SenIQ metrics, operators, risk, sizing) a custom spec may use.

POST/v1/strategies/validate

Check a Builder spec without running it. Body: the spec itself. Returns {valid, errors, normalized}.

POST/v1/backtest

Run one strategy on one symbol. Provide strategy (registry name) or custom (Builder spec). Returns metrics, trades, equity curve — and seniq_coverage when SenIQ signal factors are used.

curl -X POST https://YOUR-HOST/v1/backtest \
  -H "Authorization: Bearer $SENIQ_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "strategy": "EMACrossover",
    "params": {"fast": 20, "slow": 50},
    "symbol": "AAPL",
    "exchange": "US",
    "start_date": "2023-01-01",
    "end_date": "2024-01-01",
    "initial_cash": "100000"
  }'
FieldRequiredNotes
strategy | customone ofregistry name from the catalog, or a Builder spec
symbolyese.g. AAPL / RELIANCE / BTC
exchangenoUS · NASDAQ · NYSE · NSE · BSE · CRYPTO · COMMODITY (default US)
start_date, end_dateyesYYYY-MM-DD

POST/v1/signals

Current rule state (long/flat, last signal, fired-on-latest-bar) across up to 5 symbols.

curl -X POST https://YOUR-HOST/v1/signals \
  -H "Authorization: Bearer $SENIQ_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "strategy": "SMACrossover",
    "symbols": [{"symbol": "NVDA"}, {"symbol": "BTC", "exchange": "CRYPTO"}]
  }'

GET/v1/strategies/saved

Your saved strategies (Builder specs and configured presets) with their watchlists.

GET/v1/paper

Your paper-trading deployments (strategy, symbol, cash, deploy date, active/stopped).

GET/v1/paper/:id/state

Replay a deployment from its deploy date to now (or to when it was stopped): current equity, open position, trade log, metrics. Read-only — deploying and stopping stay in the app.

MCP server (AI agents)

The same surface is available to MCP-capable agents (Claude Desktop, Claude Code, etc.) at POST /mcp (Streamable HTTP) using the same key — tools: list_strategies · validate_strategy · run_backtest · get_signals · list_saved_strategies · list_paper_deployments · get_paper_state.

{
  "mcpServers": {
    "seniq": {
      "type": "http",
      "url": "https://YOUR-HOST/mcp",
      "headers": { "Authorization": "Bearer seniq_…" }
    }
  }
}

Errors

StatusMeaning
400invalid request — the error field explains (bad params, unknown symbol, invalid spec)
401missing, malformed, or revoked API key
403key is valid but the account isn't on the Pro plan
404unknown endpoint / strategy / deployment
429rate limit exceeded — honor Retry-After
503strategy engine offline — retry later
Backtests over custom specs that use SenIQ signal factors only reach as far back as SenIQ has been recording — check seniq_coverage in the response before trusting long-range results.
